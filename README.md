# 线上志愿者面试排表系统

自动将志愿者分配到各面试时间段和面试官组，生成结构化的排班表。

## 快速上手 用户指南

### 1. 准备输入文件

将以下两个 Excel 文件放入 `tables/` 目录：

- **面试官信息.xlsx** — 每列为一个时间段，列下逐行列出该时段的面试官姓名
- **志愿者总表.xlsx** — 包含志愿者姓名、学号、微信号、可选面试时间等列（多个时间段用全角顿号 `、` 分隔）

### 2. 修改配置

编辑项目根目录下的 `config.json`：

```json
{
    "interviewer_file": "tables/面试官信息.xlsx",
    "volunteer_file": "tables/志愿者总表.xlsx",
    "key_words": ["姓名", "学号", "微信号"],
    "interview_time_column": "面试时间",
    "sub_slot_minutes": 15,
    "enable_numbering": true,
    "distribution_strategy": 1
}
```

常用参数说明：

| 参数 | 说明 |
|------|------|
| `key_words` | 志愿者表中需要提取的列名关键字（模糊匹配） |
| `interview_time_column` | 志愿者可选时间列的匹配关键字 |
| `sub_slot_minutes` | `false` = 不分时段；填正整数（如 `15`）= 每 15 分钟切一个小时间段 |
| `enable_numbering` | `true` = 在排班表中为每位面试官下的志愿者编号 |
| `distribution_strategy` | 分配策略：`1` = 均分策略（默认）；`2` = 头部聚集策略 |

> 其余可选参数（`time_slots`、`slot_weights`、`head_gather_odd_max`、`head_gather_even_max` 等）见下方详细配置说明。

### 3. 运行

```bash
pip install -r requirements.txt   # 首次运行安装依赖
python main.py
```

### 4. 查看输出

结果生成在 `output/` 目录：

- **schedule.xlsx** — 排班表（含颜色、合并单元格）
- **schedule_log.txt** — 分配日志（统计信息 & 未分配志愿者列表）

## 整体架构

```
main.py 入口
  ├── 1. 读取 config.json 配置
  ├── 2. 解析输入文件
  │     ├── 面试官信息.xlsx → 提取时间段 & 面试官分组
  │     └── 志愿者总表.xlsx → 提取志愿者可选时间
  ├── 3. 分配算法
  │     ├── 第一轮：保底分配（每组每人至少1名志愿者）
  │     └── 第二轮：按权重分配剩余志愿者
  ├── 4. 后处理
  │     ├── 分时段：按策略将志愿者分配到小时间段
  │     │     ├── 策略1（均分）：志愿者等分到各小时间段
  │     │     └── 策略2（头部聚集）：优先填满最早的小时间段
  │     └── 编号：为每个面试官下的志愿者从 1 开始编号
  └── 5. 输出结果
        ├── output/schedule.xlsx      → 排班表
        └── output/schedule_log.txt   → 分配日志
```

## 核心流程

### 1. 数据读取与解析

#### 面试官信息解析（`InterviewerParser`）

- 读取 `面试官信息.xlsx`
- 提取所有**时间段**（作为分配的基本单元）
- 解析每个时间段对应的**面试官列表**，形成面试官分组
- 输出数据结构：`{ 时间段 → [面试官A, 面试官B, ...] }`

#### 志愿者信息解析（`VolunteerParser`）

- 读取 `志愿者总表.xlsx`
- 提取每位志愿者的**基本信息**（姓名、学号等关键字段）
- 解析每位志愿者的**可选时间段**（顿号分隔的多选时间）
- 校验志愿者可选时间与面试官时间段是否匹配
- 输出数据结构：`{ 志愿者标识 → [可选时间段列表] }`

### 2. 分配算法（`Scheduler`）

分配的目标是将志愿者分配到各时间段的面试官组中，核心约束为：

- 每位志愿者只能被分配到其**可选时间段**内
- 每个时间段的志愿者数量尽量满足**权重目标**
- 每个面试官组内至少有**1名志愿者**（保底）

#### 第一轮：保底分配

```
对每个时间段的每位面试官：
  1. 按可用时间数量对志愿者排序（时间段少的优先）
  2. 从中选取1名可用志愿者分配给该面试官
  → 确保每位面试官至少面试1名志愿者
```

#### 第二轮：按权重分配

```
对每位尚未分配的志愿者：
  1. 计算其可选时间段中各组的"缺口" = 目标人数 - 已分配人数
  2. 将该志愿者分配到缺口最大的组
  → 使各组人数尽量接近权重目标
```

#### 权重机制

- 若配置了 `slot_weights`：按比例计算每个时间段的目标志愿者数
  - 公式：`目标人数 = (该时间段权重 / 总权重) × 志愿者总数`
- 若未配置权重：所有时间段平均分配

### 3. 后处理：分时段与编号

#### 分时段（`sub_slot_minutes`）

当配置了 `sub_slot_minutes`（正整数 n）时，程序会对分配结果进行二次处理。根据 `distribution_strategy` 配置项的不同，分时段的行为有所区别：

---

##### 策略 1：均分策略（默认，`distribution_strategy: 1`）

对每个（大时间段, 面试官）分组：

1. **解析大时间段的起止时间**：从时间段名称中提取 `HH:MM-HH:MM` 部分
2. **按 n 分钟切分为小时间段**：例如 `14:00-17:00` 按 15 分钟切分为 `14:00-14:15`、`14:15-14:30`、...、`16:45-17:00`
3. **将志愿者等分到各小时间段**：每位面试官下的志愿者按顺序均匀分配到小时间段中

```
示例：大时间段 "2月25日 14:00-17:00"，sub_slot_minutes = 15
  → 切分为 12 个小时间段：14:00-14:15, 14:15-14:30, ..., 16:45-17:00
  → 该面试官下的 6 名志愿者 → 前 6 个小时间段各分配 1 人
     （若志愿者数 < 小时间段数，部分小时间段为空；
       若志愿者数 > 小时间段数，多余志愿者均匀追加到各小时间段）
```

若 `sub_slot_minutes` 未配置或为 `false`，则不进行时段切分，行为与之前一致。

---

##### 策略 2：头部聚集策略（`distribution_strategy: 2`）

该策略需同时配置以下参数：

| 参数 | 说明 |
|------|------|
| `head_gather_odd_max` | 奇数序号小时间段（第1、3、5…个）的最大人数 m |
| `head_gather_even_max` | 偶数序号小时间段（第2、4、6…个）的最大人数 n |

**核心思路**：大时间段之间仍按原有策略（权重/均分）分配志愿者总数。在每个大时间段内部，志愿者**优先填满最早的小时间段**，然后依次向后填充，直到所有志愿者分配完毕。

**详细流程**（对每个大时间段的每位面试官）：

1. 解析大时间段起止时间，按 `sub_slot_minutes` 切分为有序的小时间段列表
2. 从第 1 个小时间段开始，按顺序填充志愿者：
   - **奇数位小时间段**（第 1、3、5… 个）：最多放 `head_gather_odd_max`（m）人
   - **偶数位小时间段**（第 2、4、6… 个）：最多放 `head_gather_even_max`（n）人
3. 当前小时间段填满后，继续填充下一个小时间段
4. 所有志愿者分配完毕后，后续的小时间段**保持空置**
5. **容量校验**：若所有小时间段都填满后仍有志愿者未分配，程序输出错误信息：`"错误: 面试官不足或时间段名额太少"`

```
示例：大时间段 "2月25日 14:00-17:00"，sub_slot_minutes = 15
      head_gather_odd_max = 3, head_gather_even_max = 2
      面试官 张三 下有 10 名志愿者

  小时间段分配结果：
    #1  14:00-14:15 (奇数位, 上限3) → 3 人
    #2  14:15-14:30 (偶数位, 上限2) → 2 人
    #3  14:30-14:45 (奇数位, 上限3) → 3 人
    #4  14:45-15:00 (偶数位, 上限2) → 2 人
    #5  15:00-15:15 (奇数位, 上限3) → 0 人（空置）
    #6  15:15-15:30 (偶数位, 上限2) → 0 人（空置）
    ...
    #12 16:45-17:00                 → 0 人（空置）

  总容量 = (6个奇数位×3) + (6个偶数位×2) = 18 + 12 = 30 ≥ 10 ✓

示例（容量不足）：
  面试官 张三 下有 35 名志愿者，总容量仅 30
  → 输出错误: "错误: 时间段 '2月25日 14:00-17:00' 面试官 '张三' 名额不足
     (需分配 35 人, 总容量 30 人)"
```

---

#### 编号（`enable_numbering`）

当配置了 `enable_numbering` 为 `true` 时：

- 在最终排班表中增加一列 **"编号"**
- 编号规则：在每个**大时间段**的每位**面试官**下，志愿者从 **1** 开始顺序编号
- 不同时间段或不同面试官的编号独立计算，各自从 1 开始

```
示例：
  时间段 "2月25日 14:00-17:00" / 面试官 张三 下有 3 名志愿者 → 编号 1, 2, 3
  时间段 "2月25日 14:00-17:00" / 面试官 李四 下有 2 名志愿者 → 编号 1, 2
  时间段 "2月25日 19:00-21:00" / 面试官 张三 下有 4 名志愿者 → 编号 1, 2, 3, 4
```

- 未能分配的志愿者列表及其可选时间段（便于手动调整）
- 使用头部聚集策略时，额外输出各小时间段的填充情况和容量校验结果

## 配置文件说明

`config.json` 示例：

```json
{
    "interviewer_file": "tables/面试官信息.xlsx",
    "volunteer_file": "tables/志愿者总表.xlsx",
    "key_words": ["姓名", "学号", "微信号"],
    "interview_time_column": "面试时间",
    "interviewer_name_column": "姓名",
    "interviewer_time_column": "时间段",
    "time_slots": [],
    "slot_weights": [],
    "sub_slot_minutes": 15,
    "enable_numbering": true,
    "distribution_strategy": 1,
    "head_gather_odd_max": 3,
    "head_gather_even_max": 2
}
```

> **注意**：`time_slots` 和 `slot_weights` 均为可选项。`time_slots` 留空或不填时，程序会自动从面试官信息表中提取时间段。

### 配置项说明

| 配置项 | 必填 | 说明 |
|--------|------|------|
| `interviewer_file` | 是 | 面试官信息表路径 |
| `volunteer_file` | 是 | 志愿者总表路径 |
| `time_slots` | 否 | 时间段列表；留空或不填则自动从面试官信息表提取（按读取顺序）；若填写则用于覆盖顺序，必须与Excel中的时间格式完全一致 |
| `slot_weights` | 否 | 各时间段权重，数量必须与时间段数量一致；缺省则平均分配 |
| `key_words` | 否 | 志愿者关键字段列表，用于**模糊匹配**Excel列名（子串包含即匹配）；默认 `["姓名", "学号", "微信号"]` |
| `interview_time_column` | 否 | 志愿者可选时间列的匹配关键字（模糊匹配）；默认 `"面试时间"` |
| `interviewer_name_column` | 否 | 面试官姓名列匹配关键字（模糊匹配）；默认 `"姓名"` |
| `interviewer_time_column` | 否 | 面试官时间段列匹配关键字（模糊匹配）；默认 `"时间段"` |
| `sub_slot_minutes` | 否 | 分时段设置：`false` 表示不分时段；填写正整数 n 表示每 n 分钟切分为一个小时间段；默认 `false` |
| `enable_numbering` | 否 | 是否启用编号：`true` 时在排班表中增加编号列，每个大时间段的每位面试官下的志愿者从 1 开始编号；默认 `false` |
| `distribution_strategy` | 否 | 小时间段内的分配策略：`1` = 均分策略（志愿者等分到各小时间段），`2` = 头部聚集策略（优先填满最早的小时间段）；默认 `1`。**仅在 `sub_slot_minutes` 启用时生效** |
| `head_gather_odd_max` | 否 | 头部聚集策略下，**奇数位**小时间段（第1、3、5…个）的最大志愿者人数；**仅在 `distribution_strategy` 为 `2` 时必填** |
| `head_gather_even_max` | 否 | 头部聚集策略下，**偶数位**小时间段（第2、4、6…个）的最大志愿者人数；**仅在 `distribution_strategy` 为 `2` 时必填** |

> **模糊匹配规则**：配置的关键字只需是Excel列名的**子串**即可匹配成功。例如配置 `"学号"` 可匹配到列名 `"学号"` `"学号（8位）"` `"本人学号"` 等。同理 `"面试时间"` 可匹配 `"请选择面试时间"` `"面试时间段"` 等列名。

### 分配策略对比

| 特性 | 策略 1：均分 | 策略 2：头部聚集 |
|------|-------------|-----------------|
| 大时间段间分配 | 按权重/均分 | 按权重/均分（相同） |
| 小时间段内分配 | 志愿者等分到所有小时间段 | 优先填满最早的小时间段 |
| 后段小时间段 | 均有志愿者 | 可能为空 |
| 每段人数上限 | 无固定上限 | 奇数位 m 人、偶数位 n 人 |
| 适用场景 | 面试时间均匀分散 | 希望面试集中在前段完成 |
| 容量不足处理 | 自动均匀追加 | 报错提示 |

## 输入文件格式要求

### 面试官信息.xlsx

| 姓名 | 可面试时间段 |
|------|-------------|
| 张三 | 3月1日 周六 18:00-20:00、3月1日 周六 20:00-22:00 |
| 李四 | 3月2日 周日 14:00-16:00 |

- 必须包含含"姓名"关键字的列
- 必须包含含时间段关键字的列
- 多个时间段之间使用全角顿号（`、`）分隔

### 志愿者总表.xlsx

| 姓名 | 学号 | 微信号 | 面试时间 |
|------|------|--------|---------|
| 王五 | 202500001 | wangwu_wx | 3月1日 周六 18:00-20:00、3月2日 周日 14:00-16:00 |
| 赵六 | 202500002 | zhaoliu_wx | 3月1日 周六 20:00-22:00 |

- 列名无需与 `key_words` 完全相同，只需**包含**对应关键字即可（模糊匹配）。例如列名为 `"你的学号"` 可匹配配置中的 `"学号"`
- 可选时间列同理，列名只需包含 `interview_time_column` 配置的关键字（默认 `"面试时间"`）
- 多个时间段之间使用全角顿号（`、`）分隔
- 学号等数值型字段将以字符串读取，防止前导零丢失

## 注意事项

1. 输入文件必须放在 `tables/` 目录下（或按配置文件指定路径）
2. 配置文件中的时间段必须与Excel表格中的时间格式**完全一致**
3. `slot_weights` 数量必须与 `time_slots` 数量匹配
4. 学号等数字字段会以文本格式保存，避免出现科学计数法或丢失前导零
5. 未能分配的志愿者会在日志文件中列出，包含其可选时间段，方便手动调整
6. 程序会自动创建 `output/` 目录
7. 配置文件必须使用 UTF-8 编码保存
8. `sub_slot_minutes` 必须能整除大时间段的总分钟数，否则最后一个小时间段可能不足 n 分钟
9. 开启分时段后，时间段名称中必须包含 `HH:MM-HH:MM` 格式的时间范围，否则无法解析
10. 使用头部聚集策略（`distribution_strategy: 2`）时，必须同时配置 `head_gather_odd_max` 和 `head_gather_even_max`
11. 头部聚集策略下，若某面试官分配的志愿者总数超过所有小时间段的容量总和，程序将报错提示
